# Развёртывание

## Запуск

Из корня репозитория, Python 3.11:

```bash
python -m pip install -e '.[dev]'
python -m urbanomy_agent
```

Один процесс обслуживает:

| Адрес | Назначение |
|---|---|
| `http://localhost:8080/mcp` | MCP Streamable HTTP |
| `http://localhost:8080/a2a` | A2A JSON-RPC |
| `http://localhost:8080/.well-known/agent-card.json` | Agent Card |
| `http://localhost:8080/health` | Проверка доступности |

Параметры перечислены в `.env.example`. Дополните существующий `.env`, не
перезаписывая ключи. `.env` загружается точками входа и при создании LLM.
Общая функция `urbanomy_agent.llm.init_llm` используется и сервером, и ноутбуком.

Для LLM нужны `OPENAI_API_KEY` и `URBANOMY_LLM_MODEL`; для совместимого провайдера
задайте `OPENAI_BASE_URL`. Поддерживаются существующие `API_KEY` и `CHAT_URL`.
Ключ, адрес провайдера и модель задаются администратором, а не входным запросом.
Оценка земли и `use_llm=false` не обращаются к LLM.

Для MCP через stdio:

```bash
python -m urbanomy_mcp
```

Эквивалентные команды после установки: `urbanomy-agent`, `urbanomy-mcp`.
Старое имя команды `urbanomy-server` также сохранено.


## Настройки окружения

Пути по умолчанию отсчитываются от рабочей директории. Запускайте сервис из корня
репозитория или задайте абсолютные пути. Значения в окружении имеют приоритет над
`.env`. Образ читает данные из тома `/app/data`.

| Переменная | Значение по умолчанию / назначение |
|---|---|
| `URBANOMY_HOST` | `127.0.0.1`; в Docker `0.0.0.0` |
| `URBANOMY_PORT` | `8080` |
| `URBANOMY_PUBLIC_URL` | `http://localhost:8080`; внешний адрес для Agent Card |
| `URBANOMY_DATASETS` | `data/datasets.json` |
| `URBANOMY_OUTPUT_DIR` | `outputs/server` |
| `URBANOMY_MAX_JOBS` | `2`, положительное число параллельных расчётов |
| `URBANOMY_JOB_TIMEOUT` | `3600`, лимит расчёта в секундах |
| `URBANOMY_API_TOKEN` | Пустой: HTTP без авторизации; заданный: Bearer token |
| `URBANOMY_LLM_MODEL` | Обязательная модель для LLM-оптимизации, если нет одного из алиасов |
| `OPENAI_API_KEY` | Ключ провайдера |
| `OPENAI_BASE_URL` | Адрес OpenAI-compatible API; пустой — адрес SDK по умолчанию |

LLM-алиасы в порядке приоритета после основных переменных:
ключ — `FP2MP_API_KEY`, `CHAT_API_KEY`, `API_KEY`;
адрес — `FP2MP_CHAT_URL`, `CHAT_URL`;
модель — `FP2MP_MODEL`, `CHAT_MODEL`, `MODEL_NAME`.
Прямой аргумент `init_llm(model=...)` имеет приоритет над моделью из окружения.
Сервер создаёт LLM при необходимости, с температурой 0, таймаутом 60 секунд
и одним повтором на уровне SDK. Ноутбук может задавать другую температуру.

## Выполнение и ограничения первой версии

- Каждый расчёт выполняется в отдельном процессе. Отмена/таймаут прекращают этот
  процесс, не соседние задания; уже отправленный провайдеру LLM-запрос может быть
  обработан на его стороне. По умолчанию одновременно работают максимум два задания.
- При заполненных слотах возвращается `SERVER_BUSY`; очереди и Redis нет.
- Статусы заданий и A2A TaskStore находятся в памяти. Перезапуск останавливает
  активные задания; продолжения после перезапуска нет. Результаты, запросы, GeoJSON
  и журнал остаются в `outputs/server/<job_id>/`. MCP-статусы хранятся до 24 часов.
  Очистку файлов результатов выполняет администратор.
- Запускайте **один HTTP worker**. Для нескольких процессов/реплик нужен общий
  TaskStore и диспетчер заданий — текущая версия этого не обещает.
- Развёртывание рассчитано на одну доверенную организацию. Общий Bearer token —
  доступ к сервису, не система пользовательских ролей. MCP-клиенты с доступом к
  сервису могут обращаться к его MCP-заданиям. A2A-задачи разделены по tenant,
  но tenant во входном сообщении сам по себе не подтверждает личность.
- Нельзя менять зарегистрированные файлы во время активного запуска. SHA-256
  исходных данных и модели, CRS, обработка данных, стратегия, seed и модель LLM
  сохраняются для проверки происхождения результата. LLM не гарантирует побитовую
  воспроизводимость даже при температуре 0.
- Полный автономный поиск данных, выбор квартала по адресу и многошаговое обсуждение
  требований не добавлялись: вызывающий агент передаёт явные параметры. Экономическая
  сводка строится из измеренных результатов, без дополнительных LLM-вызовов.


## Docker

```bash
docker compose up --build -d
docker compose logs -f urbanomy
```

Предварительно создайте `.env` по примеру и предоставьте `data`.
Данные и каталог монтируются только для чтения; результаты — в отдельном томе.
HTTP-порт публикуется только на loopback хоста. Для удалённого подключения настройте
reverse proxy/TLS, публичный URL и Bearer token.
