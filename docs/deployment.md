# Настройки и развёртывание

[Запуск](../RUN.md) · [Данные](data.md) · [Запросы](tool_contract.md)

Сервер читает `.env`; переменные окружения имеют приоритет. Шаблон —
[.env.example](../.env.example). После изменения настроек перезапустите сервер.

| Переменная | По умолчанию / назначение |
|---|---|
| `DATA_DIR` | `data`; корень папок сценариев |
| `URBANOMY_OUTPUT_DIR` | `outputs/server`; результаты |
| `URBANOMY_HOST` | `127.0.0.1` |
| `URBANOMY_PORT` | `8080` |
| `URBANOMY_PUBLIC_URL` | `http://localhost:8080`; внешний адрес в Agent Card |
| `URBANOMY_API_TOKEN` | Пустой; если задан, MCP/A2A требуют Bearer token |
| `URBANOMY_MAX_JOBS` | `2`; максимум параллельных расчётов |
| `URBANOMY_JOB_TIMEOUT` | `3600`; лимит расчёта в секундах |
| `OPENAI_API_KEY` | Ключ LLM-провайдера |
| `OPENAI_BASE_URL` | Необязательный адрес OpenAI-compatible API |
| `URBANOMY_LLM_MODEL` | Модель для `use_llm=true` |

Оценка земли и оптимизация без LLM не требуют ключа. LLM вызывается с температурой 0,
таймаутом 60 секунд и одним повтором на уровне SDK.

## Настройка LLM

Для `use_llm=true` задайте в `.env`:

```dotenv
OPENAI_API_KEY=your-provider-key
URBANOMY_LLM_MODEL=your-model-name
# Только для провайдера с другим адресом API:
# OPENAI_BASE_URL=https://your-provider.example/v1
```

Модель и доступ к провайдеру настраиваются на сервере. В запросе передаются стратегия
и `use_llm`, а не API-ключ. Перезапустите сервис после изменения `.env`.

## Docker

Подготовьте `.env` и [папки сценариев](data.md), затем:

```bash
docker compose up --build -d
```

Compose задаёт `DATA_DIR=/app/data`, монтирует `./data` только для чтения,
а результаты сохраняет в том `urbanomy-results`. Данные в образ не входят.
Контейнер работает от непривилегированного пользователя; порт опубликован на
`127.0.0.1:8080`. При внешнем доступе задайте токен, HTTPS и достижимый `URBANOMY_PUBLIC_URL`.
`localhost` на удалённом клиенте не указывает на сервер Urbanomy.

## Подключение и результаты

MCP: Streamable HTTP `/mcp` или stdio `python -m urbanomy_mcp`.
Для stdio задайте рабочую директорию проекта либо абсолютные `DATA_DIR` и
`URBANOMY_OUTPUT_DIR`. A2A: `/a2a`; карточка: `/.well-known/agent-card.json`.
Проверка доступности: `/health`.

В `URBANOMY_OUTPUT_DIR/<job_id>/` сохраняются запрос, результат, GeoJSON,
прогресс, ошибка при сбое и журнал рабочего процесса.
Состояние заданий хранится в памяти: после перезапуска доступ к старым задачам через API
не восстанавливается, хотя файлы остаются. Активные расчёты останавливаются.
При заполнении слотов сервер возвращает `SERVER_BUSY`; очереди нет.

## Типичные проблемы

| Симптом | Что проверить |
|---|---|
| `SCENARIO_NOT_MATERIALIZED` | Имя из `list_scenarios`, корень `DATA_DIR`, наличие обоих файлов и том Docker |
| Сценарий виден, расчёт падает при загрузке | Обязательные столбцы, CRS, геометрии и совместимость `.cbm`; см. [требования](data.md) |
| `LLM_NOT_CONFIGURED` | Ключ и имя модели на сервере; для расчёта без LLM задайте `use_llm=false` |
| `SERVER_BUSY` | Заняты все слоты; дождитесь завершения или отмените ненужное задание |
| `NO_FEASIBLE_SOLUTION` | Совместимость границ; увеличьте бюджет поиска или пересмотрите ограничения |
| `TIMEOUT` | Серверный `URBANOMY_JOB_TIMEOUT`; при синхронном A2A также проверьте таймаут клиента |
| HTTP 401 | Совпадение Bearer token с `URBANOMY_API_TOKEN` |
| Клиент не подключается | Адрес, порт и доступность хоста со стороны клиента; `localhost` относится к самому клиенту |
| `JOB_NOT_FOUND` после перезапуска | Реестр заданий не восстанавливается; сохранённые файлы остаются в каталоге результатов |

В первую очередь смотрите причину в статусе задания. Подробности рабочего процесса —
в `URBANOMY_OUTPUT_DIR/<job_id>/worker.log`. Для контейнера журнал сервера доступен через
`docker compose logs urbanomy`. `/health` не проверяет модель и содержимое сценариев;
для этого используйте проверку с `--compute` из [инструкции запуска](../RUN.md).
