# Демонстрация и интеграция Urbanomy

Пакет для локальной проверки MCP/A2A и подключения экономического специалиста.
Серверные контракты описаны в [tool_contract.md](tool_contract.md), настройки —
в [deployment.md](deployment.md). Промпты ниже устанавливаются на стороне оркестратора.

## Демонстрационные данные

| Поле | Значение |
|---|---|
| Сценарий | `baseline` |
| Квартал | `86` — присутствует в подготовленном наборе |
| Комплект | [data/baseline](../data/baseline): GeoJSON, CatBoost `.cbm`, `scenario.json` |
| Число кварталов | 351 в исходном файле, 349 после подготовки |
| Исходная система координат | CRS84, долгота/широта |
| Границы набора | 30.0417316–30.1663108° E, 59.5319945–59.6061448° N |
| Проекция расчёта | EPSG:32636 |
| Площадь квартала 86 | 262 250,98 м², значение `site_area` из файла |
| Подготовка | Исправлены геометрии ID 277, 296, 312, 319, 342, 343; исключены 277 и 312 |
| Пропуски после подготовки | `share`: 5, `land_use`: 5, `morphotype`: 53 |

Это существующий исследовательский набор из репозитория. Его географический охват
зафиксирован координатами; дата съёмки, первичный поставщик, процедура обучения и
метрики качества модели в доступных материалах не установлены. Демо подтверждает
выполнение расчёта и интеграцию, но не точность прогноза стоимости земли.
SHA-256 данных и модели сохранены в `provenance` эталонных ответов.
Подробные требования — в [data.md](data.md).

## Эталонные запросы

| Пример | MCP-инструмент | Файл аргументов |
|---|---|---|
| Оценка земли | `estimate_land_value` | [estimate.request.json](../examples/integration/estimate.request.json) |
| Экономическая оптимизация | `start_district_optimization` | [optimize.request.json](../examples/integration/optimize.request.json) |
| Оптимизация с оценкой стратегии | `start_district_optimization` | [optimize-llm.request.json](../examples/integration/optimize-llm.request.json) |

В обоих запросах оптимизации: профиль `test`, этажность 3–6, `pop_size=4`,
`n_gen=3`, `seed=42`. Такой бюджет подходит для короткой проверки интеграции;
качество и сходимость поиска на нём не обосновываются. Эти ограничения выбраны
для демо и не представляют нормативы или согласованное задание на проектирование.

Эталонная стратегия сохранена в [optimizer-strategy.txt](../prompts/optimizer-strategy.txt).
JSON-примеры содержат её полный текст для самостоятельного использования.
Это критерий баланса интересов землепользователей, а не системная инструкция внешнего агента.

При `use_llm=false` текст сохраняется, но не влияет на поиск. При `true` сервер
добавляет собственную инструкцию формата `{"score": число}` и оценивает кандидатов
по переданным показателям. `llm_score` не является измерением общественного мнения
или проверкой реальных конфликтов между группами.

## Локальный запуск и повторение

Из корня проекта, Python 3.11–3.13:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m urbanomy_agent
```

В другом терминале:

```bash
source .venv/bin/activate
python scripts/replay_integration.py estimate
python scripts/replay_integration.py optimize
```

Скрипт проверяет наличие сценария, получает параметры квартала, запускает задание,
опрашивает его до завершения и сохраняет ответ, GeoJSON и длительность в
`outputs/integration-replay/`. Ожидаемый итог каждого вызова — `PASS`.
`--url` меняет адрес сервера, `--output` — папку результатов. При авторизации
передайте `URBANOMY_API_TOKEN` через окружение клиентского процесса.
При истечении клиентского `--timeout` (по умолчанию 600 секунд) скрипт запрашивает отмену.

Для варианта с LLM настройте ключ и `URBANOMY_LLM_MODEL` в окружении сервера
(при необходимости `OPENAI_BASE_URL`), перезапустите сервер, затем:

```bash
python scripts/replay_integration.py optimize-llm
```

Оценка стратегии вызывает настроенного внешнего провайдера. В файлах примеров
нет ключей. Режим явно задан в запросе и автоматически не меняется при ошибке.

Подключение: MCP Streamable HTTP `http://localhost:8080/mcp`,
A2A JSON-RPC `http://localhost:8080/a2a`,
Agent Card `http://localhost:8080/.well-known/agent-card.json`.
При авторизации нужен `Authorization: Bearer <token>`; для A2A — `A2A-Version: 1.0`.
Для удалённого клиента замените localhost достижимым адресом сервера.
MCP stdio также доступен через `python -m urbanomy_mcp`.

Для A2A файлы `*.a2a.json` рядом с запросами содержат конверт `SendMessage`.
Передавайте их POST-запросом на `/a2a`, затем получайте задачу через `GetTask`
с её фактическим ID. Отмена — `CancelTask`. MCP `job_id` и A2A task ID не взаимозаменяемы.

Общая стоимость земли подготовленного сценария: **75 257 912 950,24 ₽**.

После 12 оценок кандидатов получены три варианта Парето (значения округлены):

| Вариант в сохранённом ответе | Прирост стоимости земли сценария, ₽ | NPV инвестора, ₽ |
|---|---:|---:|
| 1 | 121 999 762 | 1 497 349 751 |
| 2 | −94 578 502 | 1 648 635 256 |
| 3 | −167 433 359 | 2 087 525 813 |

Отрицательный прирост допустим: в этом демо нет ограничения, запрещающего снижение
стоимости земли. Поэтому более высокий NPV может сопровождаться потерей её стоимости.
Номера строк — только порядок в данном ответе, не постоянные идентификаторы вариантов.

Сохранённые `job_id` относятся к завершённой проверке, не доступны на новом сервере
и не должны использоваться для повторных вызовов. Метаданные HTTP-прогонов:
[estimate.run.json](../examples/integration/estimate.run.json),
[optimize.run.json](../examples/integration/optimize.run.json).
Первый HTTP-прогон включал создание кэша шрифтов Matplotlib, поэтому его полная
длительность не сопоставима с замерами расчётного сервиса ниже.
Оба HTTP MCP-примера и `smoke_server.py --compute` (MCP + A2A) завершились с `PASS`.
Сохранённые результаты проверены на совпадение хешей, число геометрий, конечность
экономических показателей, сумму долей и соблюдение effective_constraints.

Сохранённые ответы и `*.run.json` отражают исходный прогон. После него из текущей
strategy удалена случайно добавленная инструкция о диапазоне оценки; исторические
файлы не переписывались. В проверенном режиме `use_llm=false` это не меняет расчёт,
а формат LLM-ответа по-прежнему задаётся кодом scorer.

**LLM-вариант:** запрос и стратегия подготовлены, реальный вызов провайдера пока
не выполнен. Эталонного `llm_score` в пакете нет; проверенные результаты выше получены
с `use_llm=false`.

## Критерии приёмки результатов

- Оба расчёта завершаются успешно; итог содержит выбранный `target_id=86` и provenance.
- Для оценки: положительные `land_value` и `land_value_per_sqm`, валюта `RUB`.
  При совпадении хешей данных и модели сравнивайте с эталоном с относительным
  допуском `1e-6` или абсолютным 1 рубль — используйте больший допуск.
- Для оптимизации: непустой `scenarios`, конечные экономические показатели,
  доли землепользования с суммой 1; значения из `params_repaired` укладываются
  в `effective_constraints` с числовым допуском. Включённый LLM добавляет score от 0 до 1.
- GeoJSON — `FeatureCollection` в WGS84. Для оценки он содержит подготовленные кварталы,
  для оптимизации — варианты с одинаковой геометрией выбранного квартала.
- Сравнивайте расчётные поля, а не `job_id`, время и порядок вариантов.
  Версии библиотек и ответы LLM могут менять фронт Парето даже при фиксированном seed.

Стоимость земли и её прирост относятся ко всему сценарию там, где используются
`dataset_land_value_total`, `land_value_after` и `land_value_gain`.
`land_value` — стоимость выбранного квартала, `investor_npv` — NPV его развития.
Единственный лучший вариант без критерия пользователя не выбирается.

## Ресурсы и методика

Замеры выполняются локально через тот же `UrbanomyService` и реальные рабочие процессы.
Скрипт [benchmark_integration.py](../scripts/benchmark_integration.py) запускает три повтора
оценки, три повтора оптимизации и три пары одновременных оптимизаций. LLM отключён.
Для повторения нужна необязательная зависимость измерений `psutil`:

```bash
python -m pip install psutil
python scripts/benchmark_integration.py --output outputs/integration-benchmark
```

RSS и CPU дерева процессов опрашиваются каждые 0,1 секунды. RSS суммируется по процессам
и может повторно учитывать общие страницы. Это наблюдаемый пик, не точное максимальное
потребление физической памяти. CPU — приблизительная оценка по выборкам; 100% означает
одно логическое ядро, 200% — два. Время включает запуск workers, расчёт, запись файлов
и опрос состояния. HTTP-обвязка и LLM в эти замеры не входят. Время конструктора сервиса
в JSON не является временем полной готовности сервера.

### Измерения 8 сентября 2026 года

Хост: macOS 26.6.2, ARM64, 10 логических ядер, 16 GiB RAM, Python 3.11.8.
Версии расчётных библиотек и все девять измерений — в
[benchmark.json](../examples/integration/benchmark.json).

| Нагрузка | Медиана времени, с | Максимум суммарного RSS, MiB | Средняя загрузка CPU по прогонам |
|---|---:|---:|---:|
| Оценка земли | 3.164 | 469.0 | 88.1–103.5% |
| Одна оптимизация | 7.080 | 508.5 | 105.0–105.4% |
| Две оптимизации одновременно | 7.662 | 962.7 | 195.5–203.3% |

Для пары время измерено до завершения обоих заданий. Замеры сделаны на рабочем
компьютере, не на изолированном стенде; фоновые процессы могут влиять на длительность.
Для одного локального демо разумная стартовая конфигурация — 2 CPU и 2 GiB свободной
RAM для сервиса; для двух одновременных — 2 CPU и 3 GiB. Это оценка с запасом относительно
наблюдаемого RSS, а не измеренный минимум или гарантия для другого окружения.
Локальная LLM в эти рекомендации не включена.

Числа относятся только к приложенному набору и короткому бюджету поиска. Они не являются
SLA; для другой территории, большего бюджета и другого хоста нужны отдельные измерения.

## Конфигурация агентов

- [urbanomy-specialist.md](../prompts/urbanomy-specialist.md) — постоянные инструкции
  внешнего экономического специалиста с MCP-инструментами.
- [urbanomy-routing.md](../prompts/urbanomy-routing.md) — правило маршрутизации для
  оркестратора; конкретный инструмент делегирования задаётся его конфигурацией.
- [optimizer-strategy.txt](../prompts/optimizer-strategy.txt) — пользовательский критерий,
  передаваемый в strategy конкретного запроса.

[Инструкция подключения](../prompts/README.md) описывает установку текстов, доступные
инструменты, хранение состояния и возобновление заданий. Для специалиста доступны
9 инструментов из [каталога](mcp_tool_catalog.md). Через прямой A2A вызывающая сторона
передаёт структурированные параметры и должна заранее разрешить обязательные поля.

Параметры демо передавайте отдельным запросом из examples/integration, не включайте
их в постоянные системные инструкции. [Сценарии проверки агентов](../examples/integration/agent-evals.md)
также хранятся отдельно. Они покрывают продолжение заданий, изменение параметров,
ошибки, отмену и маршрутизацию; пока не прогнаны на целевой модели в Synapse.
Локальные проверки API не подтверждают поведение LLM-агента или работу внешнего планировщика.
