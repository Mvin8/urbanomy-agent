# Контракт инструментов и агента

[Индекс](README.md) · [Каталог MCP](mcp_tool_catalog.md) · [Карточка A2A](a2a_agent_card.md)

## Данные и выбор квартала

`data/datasets.json` — каталог разрешённых наборов данных. Пути в нём считаются
относительно файла каталога (`data/`). В запросах передаётся `dataset_id`, а не путь или URL.
Для нового набора зарегистрируйте GeoJSON и обученную CatBoost-модель:

```json
{
  "my_district": {
    "description": "Подготовленные кварталы района",
    "blocks_path": "my_district.geojson",
    "model_path": "land_value.cbm"
  }
}
```

Модель должна соответствовать признакам `LandPriceEstimator` и предсказывать
`log1p` общей стоимости квартала в рублях. Сервер применяет `expm1` и делит общую
стоимость на `site_area` для цены за м². Иная целевая переменная требует адаптации.

Стандартный набор `baseline` использует файлы из `data`. Они не включены
в Docker-образ: их нужно предоставить отдельно. Сохраняются исходные `id`, без
перенумерации и без удаления кварталов по перцентилю цены, как в исследовательском
ноутбуке. Строка `"86"` и числовой ID `86` находят один и тот же квартал.

Географические координаты переводятся в локальную UTM для расчёта соседства
в метрах. Исходные `site_area` и остальные признаки не пересчитываются.
GeoJSON-результаты выдаются в WGS84. Используется всё окружение из набора данных.
При очень большой территории заранее подготовьте подходящую метрическую проекцию.

По умолчанию плохие геометрии отклоняются. Для приложенного `baseline` явно включён
`geometry_policy: "repair_and_drop_non_polygon"`: `make_valid`, сохранение площадных
частей и исключение вырожденных объектов. ID исправленных и исключённых кварталов
сохраняются в `provenance`. Исходный файл не меняется. Пропуски признаков также
перечисляются в `provenance`; обработка остаётся как в исходном оценщике: числовые
NaN допускаются CatBoost, для пространственных лагов используется среднее,
категории получают метку `missing`. Бесконечности и неположительная площадь запрещены.


## Выбор ограничений и стратегия

Сначала вызовите `list_datasets`, `list_blocks` и `get_optimization_options`.
Последний инструмент вернёт геометрию квартала, текущие значения, единицы и пределы.
ID можно передать из выбора на карте. Неоднозначный выбор должен уточнить вызывающий
агент: сервер не выбирает квартал по свободному описанию и не придумывает ограничения.

Независимые параметры: `footprint_area`, `l` и семь долей землепользования:
`residential`, `business`, `recreation`, `industrial`, `transport`, `special`, `agriculture`.
`l` — средняя этажность, непрерывное число, не целое количество этажей каждого здания.

Неуказанные независимые параметры фиксируются на исходных значениях; исходные
доли перед этим нормализуются до суммы 1. Чтобы менять распределение долей,
задавайте диапазоны всех долей, которые разрешено изменять. Сервер проверяет,
что нижние/верхние границы допускают сумму 1, и сохраняет их при нормализации.
Ограничение `min == max` фиксирует параметр.

`mxi`, `fsi`, `gsi`, `build_floor_area`, `living_area`, `non_living_area`, `population`
— ограничения на **пересчитанный итоговый сценарий**, а не дополнительные свободные
переменные. Например, текущая модель связывает `mxi` с долей жилья через коэффициент
0.8: независимо варьировать эти два значения нельзя. Ограничения проверяются после
`ScenarioTEPModifier`, до LLM-вызова. Для чисел применяется относительный допуск `1e-9`.

Площадь застройки ограничена 80% `site_area`, как в исходном оптимизаторе.
Нулевая нижняя граница разрешена, но итоговая площадь застройки должна быть положительной,
иначе плотностные показатели не определены. `l >= 1`.
Невыполнимый набор или отсутствие допустимого решения в бюджете возвращается ошибкой.
Сервер не ослабляет заданные границы автоматически.

`strategy` — предпочтения для LLM. На уровне общей схемы и A2A принимается также
имя `prompt`; MCP публикует одно поле `strategy`. Постоянная инструкция оценщику
отделена от стратегии и требует JSON `{"score": 0..1}`. В течение запуска стратегия
не меняется. Её изменение означает новый запуск.

Оценщик видит параметры сценария, прирост стоимости земли по всему набору и NPV
выбранного квартала. Критерии вроде доступности школ нельзя считать измеренными:
таких метрик в этом payload нет. `use_llm=false` оставляет две экономические цели;
стратегия сохраняется как контекст, но не влияет на отбор.


## MCP

| Инструмент | Результат |
|---|---|
| `list_datasets` | Каталог наборов |
| `list_blocks` | Страница кварталов: `offset`, `limit` (до 200) |
| `get_optimization_options` | Геометрия, исходные значения и доступные ограничения |
| `estimate_land_value` | Запуск оценки, возвращает `job_id` |
| `start_district_optimization` | Запуск оптимизации, возвращает `job_id` |
| `get_job_status` | Состояние и число оценённых кандидатов |
| `get_job_result` | Оценка или варианты Парето, метрики и сводка |
| `get_job_geojson` | Пространственный результат |
| `cancel_job` | Остановка процесса конкретного расчёта |

Пример аргументов `start_district_optimization`:

```json
{
  "dataset_id": "baseline",
  "target_id": 86,
  "constraints": {"l": {"min": 1, "max": 8}},
  "strategy": "Предпочитать умеренную плотность и сочетание жилых и деловых функций.",
  "use_llm": true,
  "pop_size": 20,
  "n_gen": 20,
  "seed": 42
}
```

В этом примере меняется только этажность; состав функций фиксирован. Чтобы искать
и другое распределение функций, добавьте соответствующие диапазоны долей.
Идентификатор задания относится к процессу сервера, не к отдельной HTTP-сессии MCP.
Проверяйте состояние раз в несколько секунд до `completed`, `failed` или `canceled`.


## A2A и Codesynapse

Agent Card объявляет A2A 1.0 и обязательное расширение со схемой входных данных.
Codesynapse извлекает базовые поля по этой схеме. Для ограничений объявлено строковое
поле `constraints_json`, поскольку его извлечение надёжнее вложенной схемы в текущем
Codesynapse. Прямой клиент или static workflow может передать обычный `constraints`.
Одновременно оба поля запрещены. Вход полностью проверяется на сервере.

Для ручного вызова нужен заголовок `A2A-Version: 1.0`; без него SDK предполагает 0.3
и отклоняет запрос. При настроенном токене добавьте `Authorization: Bearer ...`.

```json
{
  "jsonrpc": "2.0",
  "id": "request-1",
  "method": "SendMessage",
  "params": {
    "tenant": "your-tenant",
    "message": {
      "messageId": "message-1",
      "contextId": "workflow-run-1",
      "role": "ROLE_USER",
      "parts": [{"data": {
        "operation": "optimize_district",
        "dataset_id": "baseline",
        "target_id": "86",
        "constraints_json": "{\"l\":{\"min\":1,\"max\":8}}",
        "strategy": "Предпочитать умеренную плотность.",
        "use_llm": true,
        "pop_size": 20,
        "n_gen": 20
      }}]
    },
    "configuration": {"returnImmediately": true}
  }
}
```

`returnImmediately=true` возвращает рабочую задачу. Затем `GetTask` с
`{"id":"<task-id>","tenant":"your-tenant"}` возвращает её состояние и результат;
`CancelTask` с теми же параметрами останавливает работу. `returnImmediately=false`
ожидает завершения. `SendStreamingMessage` передаёт статусы и артефакты через SSE.
Поддерживаются также имена из документации Codesynapse: `message/send`,
`message/stream`, `tasks/get`, `tasks/cancel`. Это алиасы имён методов, а не поддержка
формата A2A 0.3. Ответ `SendMessage` содержит `result.task`.

Для оценки земли нужны только `operation: "estimate_land_value"`, `dataset_id`,
`target_id`. Для оптимизации стратегия берётся из `strategy`/`prompt`; если их нет,
используется текстовая часть сообщения. Явные структурированные поля имеют приоритет.
Ошибки входа возвращаются как `TASK_STATE_FAILED` с причиной в `status.message`.
Не используется `INPUT_REQUIRED`: Codesynapse не открывает по нему диалог с человеком.

Регистрация в Codesynapse:

1. Разверните сервер на доступном API-хосту Codesynapse адресе. Укажите этот адрес
   в `URBANOMY_PUBLIC_URL`. `localhost` из браузера не является адресом удалённого API.
2. MCP: Discover → HTTP Streamable → `https://<host>/mcp` → импорт инструментов.
3. A2A: endpoint `https://<host>`, Agent Card
   `https://<host>/.well-known/agent-card.json`, RPC endpoint `/a2a`.
4. Если настроен токен, задайте Bearer credentials для обоих подключений.
5. Согласуйте таймауты. В приложенном Codesynapse отправляется
   `returnImmediately=false`: обычный `SendMessage` ждёт результат. Для такого режима
   `request_timeout_seconds` должен превышать `URBANOMY_JOB_TIMEOUT` с запасом;
   таймаут workflow также должен позволять завершить расчёт. Альтернатива — streaming,
   если он включён в выбранном пути клиента. Для клиентов с `returnImmediately=true`
   используйте polling. Agent delegation в приложенном Codesynapse самостоятельно
   polling не запускает: ему нужен конечный ответ или поток до конечного события.

Артефакты A2A содержат сводку, JSON с результатами и GeoJSON, а не локальные пути.
`land_value_after`/`land_value_gain` в сценариях относятся ко всему набору кварталов,
`investor_npv` — к выбранному кварталу. Варианты используют одну геометрию квартала
с разными параметрами: оптимизатор не проектирует контуры зданий.


## Ответы и ошибки

MCP использует обычный `CallToolResult`: успешный JSON находится в
`structuredContent`, а копия представлена текстовой частью. Ошибки проверки
инструмента возвращаются с `isError=true`. Принятое задание может затем завершиться
с `status: "failed"`: это результат фонового расчёта, а не транспортная ошибка.

| Ситуация | Наблюдаемый результат |
|---|---|
| Неизвестное поле/неверные границы | Ошибка схемы до запуска; MCP `isError`, A2A failed Task |
| Набор не зарегистрирован | Ошибка до запуска |
| Квартал не найден или данные некорректны | Фоновое задание `failed`, `CALCULATION_FAILED` |
| Нет допустимого решения в бюджете | `CALCULATION_FAILED`, сообщение начинается с `NO_FEASIBLE_SOLUTION` |
| LLM не настроен | `CALCULATION_FAILED`, сообщение начинается с `LLM_NOT_CONFIGURED` |
| Все процессы заняты | `SERVER_BUSY` до запуска |
| Превышен лимит времени | `failed`, `TIMEOUT` |
| Процесс вышел без результата | `failed`, `WORKER_EXITED` |
| Неизвестный или чужой job ID | `JOB_NOT_FOUND` |
| Расчёт отменён | `canceled`; готовый результат не подменяется |
| Неверный Bearer token | HTTP 401; публичные health и Agent Card доступны |

Пример успешного запуска (идентификатор условный):

```json
{"job_id":"example-job","operation":"optimize_district","status":"working","elapsed_seconds":0.0}
```

`get_job_result` добавляет поле `result` только после завершения. Для оценки оно
содержит `land_value`, `land_value_per_sqm`, `dataset_land_value_total`, `currency`,
`summary`, `provenance`. Для оптимизации — `scenarios`, `effective_constraints`,
`baseline_land_value_total`, `strategy`, `use_llm`, `evaluations`, `summary`, `provenance`.
Оба результата содержат `target_id`. Детали файлов и времени жизни:
[развёртывание](deployment.md#выполнение-и-ограничения-первой-версии).
