# Данные и модель

## Размещение

`DATA_DIR` задаёт корневую папку данных: локально `data`, в Docker `/app/data`.
Каждый сценарий — отдельная папка:

```text
DATA_DIR/<scenario_id>/
├── blocks_agg_with_indicators.geojson
├── catboost_land_value_no_services.cbm
└── scenario.json
```

Первые два файла обязательны, их имена фиксированы. В `scenario.json` можно включить
`{"geometry_policy":"repair_and_drop_non_polygon"}`. Без него плохие геометрии отклоняются.

Для добавления сценария разместите подготовленные файлы в новой папке и вызовите
`list_scenarios`. Отдельная регистрация не нужна. Каталог показывает папки с обоими
обязательными файлами. Содержимое проверяется при чтении и расчёте.

`scenario_id` — имя папки, `target_id` — значение `id` квартала.
Необязательный `project_id` сохраняется в `provenance` и не влияет на выбор данных.
Идентификаторы сценария и проекта: латинские буквы, цифры, `_`, `-`, длина 1–64.
Пути и символические ссылки не могут выходить за `DATA_DIR`.
MCP и A2A используют один загрузчик.

Нет папки или обязательного файла → `SCENARIO_NOT_MATERIALIZED` с перечнем доступных
сценариев. Папки с неполным комплектом не отображаются в каталоге.
Загрузка по URL, загрузка файлов через инструменты и получение данных из БД не реализованы.

## Добавление своего сценария

1. Подготовьте кварталы с признаками из таблицы ниже и совместимую CatBoost-модель.
2. Создайте, например, `data/my_district/` и поместите в неё оба обязательных файла
   с фиксированными именами. Если нужна обработка плохих геометрий, добавьте `scenario.json`.
3. Вызовите `list_scenarios`: в ответе должен появиться `my_district`. Новая папка
   обнаруживается при следующем вызове, перезапуск сервера не нужен.
4. Вызовите `list_blocks` с `{"scenario_id":"my_district","limit":10}` и выберите ID.
5. Запустите `estimate_land_value` для этого ID. Это проверит загрузку и соответствие
   признаков модели. Успешное появление папки в каталоге ещё не проверяет её содержимое.

Для корня данных вне проекта задайте абсолютный путь, например `DATA_DIR=/srv/urbanomy/data`.
В Docker измените исходную папку тома в `compose.yaml`. Путь внутри контейнера
остаётся `/app/data`. В запросах передавайте только имя сценария, без полного пути.

### Сценарий, квартал и задание

| Идентификатор | Что обозначает | Пример |
|---|---|---|
| `scenario_id` | Подготовленную территорию и модель в папке | `my_district` |
| `target_id` | Квартал внутри этой территории | `86` |
| `project_id` | Необязательную внешнюю метку проекта | `pilot-1` |
| `job_id` | Отдельный запуск расчёта. ID выдаётся сервером | Непрозрачная строка |

Одна папка сценария может использоваться во многих заданиях. Варианты, найденные
оптимизатором, возвращаются в результате задания и не создают новые папки исходных данных.

## Требования к GeoJSON

Это подготовленные кварталы с геометрией и признаками, а не сырые контуры зданий.

| Поля | Содержание |
|---|---|
| `id`, `geometry` | Уникальный непустой ID, непустая корректная геометрия |
| `residential`, `business`, `recreation`, `industrial`, `transport`, `special`, `agriculture` | Доли землепользования |
| `site_area`, `footprint_area` | Площадь квартала и пятна застройки, м² |
| `build_floor_area`, `living_area`, `non_living_area` | Поэтажная, жилая и нежилая площади, м² |
| `population`, `l` | Население и средняя этажность |
| `share`, `fsi`, `gsi`, `mxi`, `area_accessibility` | Подготовленные признаки модели |
| `land_use`, `morphotype` | Категориальные признаки |

CRS обязателен. Географические координаты переводятся в локальную UTM.
Для расчётов нужна проекция в метрах. `site_area` должна быть конечной и положительной.
Исходные площади и другие признаки из геометрии автоматически не пересчитываются.
Числовые бесконечности запрещены. Пропуски учитываются в `provenance` и обрабатываются
оценщиком. Для оптимизации нужны определённые исходные значения фиксируемых параметров.

Отдельные файлы сервисов и матрица доступности не нужны. `area_accessibility` должна
быть подготовлена заранее. Пространственные признаки окружения вычисляются при расчёте
для радиусов 500, 1000, 2000 и 3000 м. Передавайте кварталы вместе с окружением:
его состав влияет на результат.

## Требования к модели

CatBoost-модель должна соответствовать признакам оценщика и предсказывать
`log1p` **общей стоимости земли квартала в рублях**. Сервер применяет `expm1`,
а цену за м² получает делением на `site_area`. Обучение модели и подготовка новых
территорий выполняются отдельно. Совместимость полей не гарантирует качество прогноза.

## Передача и воспроизводимость

Стандартный `baseline` включён в репозиторий. В Docker-образ данные не входят:
`compose.yaml` монтирует `./data:/app/data:ro`. При передаче только образа приложите
папку данных отдельно. Новые папки сценариев также нужно включить в передачу.

Не изменяйте файлы во время расчёта. В `provenance` сохраняются SHA-256 GeoJSON и модели,
CRS, исправленные и исключённые ID, сведения о пропусках и идентификаторы контекста.
Результирующий GeoJSON выдаётся в WGS84. Исходные файлы не меняются.

При передаче проверьте комплект:

- Код и зависимости из `pyproject.toml`.
- Все используемые папки сценариев с GeoJSON и `.cbm`, а при наличии — `scenario.json`.
- Значения `DATA_DIR` и способ монтирования для выбранного окружения.
- Описание источников, даты данных, расчёта признаков, обучающей выборки и качества модели.
