# Urbanomy

Оценка стоимости земли и подбор вариантов застройки квартала через MCP и A2A.
CatBoost рассчитывает стоимость земли, NSGA-II ищет компромисс между её приростом
и NPV инвестора. LLM опционально оценивает соответствие текстовой стратегии.

## Возможности

| Задача | Что получаете |
|---|---|
| Оценить землю | Стоимость квартала, цену за м² и оценки кварталов окружения |
| Найти варианты застройки | Допустимые варианты с параметрами, приростом стоимости земли и NPV |
| Учесть текстовую стратегию | Дополнительную оценку `llm_score` при включённой LLM |
| Выполнить долгий расчёт | Фоновое задание со статусом, прогрессом и отменой |

Сервис рассчитан на подготовленные геоданные. Он не ищет участок по адресу,
не собирает исходные данные и не создаёт генплан. Для показа результатов на карте
подключённый клиент может использовать возвращаемый GeoJSON.

## Запуск

Нужны Python 3.11–3.13 и файлы стандартного сценария из `data/baseline/`.
Команды для macOS/Linux, из корня полученного репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m urbanomy_agent
```

Настройки — в [.env.example](.env.example). Для оценки земли и оптимизации
с `use_llm=false` ключ LLM не нужен. Для настройки скопируйте шаблон в `.env`,
если этого файла ещё нет. Существующий файл дополните нужными значениями.

Во втором терминале проверьте сервер и настоящий расчёт:

```bash
source .venv/bin/activate
python scripts/smoke_server.py --compute
```

При успехе скрипт завершится строкой `PASS`. Он проверяет оценку земли через MCP
и короткую оптимизацию через A2A без обращения к LLM. `/health` подтверждает только
доступность сервера. Проверка с `--compute` также проверяет данные и модель.

### Подключение клиента

- MCP Streamable HTTP: `http://localhost:8080/mcp`
- A2A JSON-RPC: `http://localhost:8080/a2a`
- Agent Card: `http://localhost:8080/.well-known/agent-card.json`
- MCP stdio: `python -m urbanomy_mcp`

В MCP-клиенте выберите Streamable HTTP и адрес `/mcp`. Для stdio укажите Python
из окружения `.venv`, аргументы `-m urbanomy_mcp` и рабочую директорию проекта.
При настроенном `URBANOMY_API_TOKEN` HTTP-запросам нужен `Authorization: Bearer <token>`.

Docker: подготовьте `.env`, затем `docker compose up --build -d`.
[Подробный запуск](RUN.md) · [Настройки и диагностика](docs/deployment.md).

## Данные

Сервер читает готовые сценарии из `DATA_DIR/<scenario_id>/`. По умолчанию `DATA_DIR=data`.
Стандартный сценарий включён в репозиторий:

```text
data/
└── baseline/
    ├── blocks_agg_with_indicators.geojson
    ├── catboost_land_value_no_services.cbm
    └── scenario.json
```

GeoJSON содержит кварталы с рассчитанными признаками, `.cbm` — обученную модель.
Оба файла обязательны. `scenario.json` необязателен. У `baseline` он включает
исправление геометрий. Для нового сценария создайте папку с таким же комплектом.

`list_scenarios` возвращает доступные сценарии, `list_blocks` — ID кварталов.
`scenario_id` выбирает папку, `target_id` — квартал, `project_id` служит только меткой проекта.
Через запросы файлы не загружаются. В Docker данные монтируются из `./data` в
`/app/data` только для чтения. В образ они не включены.

[Требования к данным и модели](docs/data.md).

## Первый расчёт

Через подключённый MCP-клиент последовательно вызовите инструменты:

| Шаг | Инструмент | Аргументы |
|---|---|---|
| 1 | `list_scenarios` | `{}` |
| 2 | `list_blocks` | `{"scenario_id":"baseline"}` |
| 3 | `estimate_land_value` | `{"scenario_id":"baseline","target_id":86}` |
| 4 | `get_job_status` | `{"job_id":"<полученный ID>"}` |
| 5 | `get_job_result` | Тот же `job_id`, после `completed` |

Для другого сценария используйте ID из каталога и его списка кварталов.
Это вызовы MCP-инструментов, а не отдельные HTTP-маршруты.

Пример основных полей результата для приложенного `baseline`, квартала `86`
(округлено, внутри поля `result` ответа):

```json
{
  "target_id": 86,
  "land_value": 720316894.48,
  "land_value_per_sqm": 2746.67,
  "dataset_land_value_total": 75257912950.24,
  "currency": "RUB"
}
```

`land_value` — модельная стоимость земли выбранного квартала, а
`dataset_land_value_total` — сумма по всем кварталам сценария. При изменении
данных или модели числа могут измениться. `get_job_geojson` возвращает границы
с оценками для отображения на карте.

## Пример оптимизации

Сначала вызовите `get_optimization_options` для выбранного квартала: он вернёт
исходные параметры и единицы. Затем передайте `start_district_optimization`:

```json
{
  "scenario_id": "baseline",
  "target_id": 86,
  "constraints_profile": "test",
  "strategy": "Предпочитать смешанное жилое и деловое использование",
  "use_llm": false,
  "pop_size": 20,
  "n_gen": 30,
  "seed": 42
}
```

Профиль `test`: пятно застройки 1 м²–10% площади квартала, этажность 1–10,
MXI 0,1–1, семь долей землепользования 0–1 с суммой 1.
Поле `constraints` переопределяет границы профиля по параметрам.
Без профиля неуказанные параметры фиксируются на исходных значениях.
При `use_llm=false` стратегия сохраняется, но не влияет на поиск.

Например, чтобы ограничить этажность сильнее, добавьте в запрос:

```json
{
  "constraints": {"l": {"min": 3, "max": 6}}
}
```

Чтобы включить оценку стратегии, настройте `OPENAI_API_KEY`, `URBANOMY_LLM_MODEL`
и при необходимости `OPENAI_BASE_URL`, затем передайте `use_llm: true`.


Оба инструмента возвращают `job_id`. Проверяйте `get_job_status` до завершения,
затем получите `get_job_result` и при необходимости `get_job_geojson`.
Результат содержит числа, сводку и геоданные. Оптимизация возвращает варианты
с параметрами застройки. Расположение отдельных зданий не проектируется.
Прирост стоимости земли относится ко всему сценарию, NPV — к выбранному кварталу.
Варианты показывают компромиссы между целями. Лучший вариант выбирает пользователь.

### Если расчёт занимает 20 минут

Сервер возвращает `job_id` сразу. Проверяйте статус каждые 10–15 секунд:
`working` → `completed`, `failed` или `canceled`.
Доступны прошедшее время и число обработанных кандидатов. Прогноза времени пока нет.
Для остановки используйте `cancel_job`. Лимит по умолчанию — 60 минут.
Перезапуск сервера прерывает активные задания.
